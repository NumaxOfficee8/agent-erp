# AgentERP Phase 1 成果驗收說明書 (Walkthrough)

本說明書記載 Phase 1「模組動態插拔與自訂 SVG 選單架構」之開發完成狀況與本地驗證流程。

---

## 1. 已完成之核心功能與改動

### 1.1. 雲端清單同步與下載（模組市集）
* 前端 `store.svelte.js` 新增了 `fetchModulesGallery` 雲端市集清單同步與 `installModuleAction` 按鈕控制方法。
* 在本地開發時，若無法連線雲端，市集清單將自動降級（Fallback）使用預設的 Mock 模組清單（Finance BI 大看板與 CRM 客戶模組）以便測試。
* 前端「設定與市集管理」分頁新增了「**雲端擴充模組市集 (Module Gallery)**」介面卡片。

### 1.2. 側邊欄動態選單與自訂 SVG 渲染
* 重構 [App.svelte](file:///Users/peter/Codes/numax/erp-agent/src/App.svelte)，徹底移除了左側導覽列中寫死的 `finance` 與 `crm` 欄位。
* 左側導覽列改為讀取 `appState.installedModules` 資料，並使用 Svelte 的 `{@html mod.iconSvg}` 語法動態將模組聲明的自訂 SVG 圖示無縫渲染在選單中。

### 1.3. 選單切換之狀態保留（Keep-Alive 機制）
* 修改了 `App.svelte` 視窗視域（Viewport）的渲染邏輯，各個已載入的模組元件將常駐在 DOM 樹中。
* 切換工作區時，前端僅透過 `.workspace-panel.hidden { display: none !important; }` 切換可見性。這保證了在財務 BI 或 CRM 試算時，拉動的滑桿數值、表單輸入或滾動位置在切換分頁後 **100% 完美保留**，不會重置。

### 1.4. Rust SVG 安全過濾器 (SVG Sanitizer)
* 在 [downloader.rs](file:///Users/peter/Codes/numax/erp-agent/src-tauri/src/downloader.rs) 寫入本地 SQLite 庫前，新增了 `sanitize_svg` 防禦函數。
* 執行 **4000 字元長度限制**防禦，且徹底過濾黑名單標籤（如 `<script>`, `<iframe>`）與行內監聽事件（如 `onload`, `onclick`），保證動態載入的安全性。

### 1.5. 模組專屬 SQLite 安全建表機制（Option B）
* 在 `lib.rs` 註冊了 `initialize_module_db` IPC 通道。
* 該命令會進行嚴格的 SQL 審計，限制只能執行 `CREATE TABLE`，禁止 `DROP`/`ALTER`/`DELETE`，且強制資料表必須以 `module_{module_id}_` 為前綴（如 `module_sales_bi_cache`），保障核心資料庫的完全隔離。
* 調整了 `sales_bi_module.js` 動態組件，在被掛載（onMount）時會自動向 Tauri 發送 IPC 請求，動態初始化其專屬的 SQLite 資料表。

## 2. 本地驗證與操作指南

請在專案根目錄下執行以下指令啟動桌面開發環境：
```bash
npm run tauri dev
```

### 驗證步驟一：側邊欄動態 SVG 選單與市集下載
1. 開啟 App 時，左側導覽列將**只有**內建的「銷售與訂單」和「設定與市集管理」兩個選單（其餘選單均被成功解耦移除）。
2. 切換至「設定與市集管理」分頁，點擊「雲端擴充模組市集」底下的「**同步商店清單**」按鈕，畫面上將動態出現可用模組的列表與介紹。
3. 點擊「**Finance BI 大看板**」右側的「**下載安裝**」：
   * 系統會將 mock 模組包下載並校驗安全性（過濾 SVG）。
   * 註冊進 SQLite。
   * **左側側邊欄將即時（Reactively）生出該模組特有的紫色 BI 直條圖 SVG 選單圖示**！
4. 同理，點擊下載「**CRM 客戶模組**」，側邊欄會即時生出藍色的 CRM 用戶群頭像 SVG 圖示。

### 驗證步驟二：Keep-Alive 狀態保留
1. 點選側邊欄中剛加載出來的「Finance BI 大看板」選單。
2. 拖曳「產能利潤率敏感度模擬器」滑桿，將利潤率調至任意自訂值（例如 `35%`，此時產能利用率會即時跟著變動）。
3. 點選其他任意分頁（如「銷售與訂單」或「設定」），隨便做些操作。
4. 重新點回「Finance BI 大看板」，**驗證滑桿的位置與利潤率數字依然是剛才設定的 `35%`，數據完全沒有遺失重置**！

### 驗證步驟三：模組專屬 SQLite 安全建表
1. 當您首次點擊切換至「Finance BI 大看板」時，該動態 Svelte 元件會在背後調用 `initialize_module_db`。
2. 您可以在終端機的 Log 輸出中看見：
   `Module 'sales_bi' dynamically initialized table 'module_sales_bi_cache'`
   這說明模組已經安全、動態地在本地 SQLite 中建置了專屬表，而不需要修改任何外殼代碼！
